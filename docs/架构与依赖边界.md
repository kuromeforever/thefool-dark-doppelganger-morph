# 架构与依赖边界

最后更新：2026-08-28

## 所有权

| 层 | 拥有内容 | 不拥有内容 |
| --- | --- | --- |
| Dark Doppelganger | Boss/仆从类型、AI、法术、动画、持久仆从、原始资源 | BetterMorph 目录、AOM 冷却、中文补丁 |
| AOM | Morph API v1.1、Ability、轮盘、唯一玩家冷却、原生法术协调器、终焉 Boss 入口 | 来源专用五技能、来源汉化、附属发布 |
| BetterMorph | identity 渲染、玩家形态同步、基础变身生命周期 | 本附属业务伤害、法术和中文 |
| 本附属 | provider 声明、五技能、短动作会话、来源中文、精确来源合同 | 通用轮盘、第二套冷却、来源实体持久数据 |

依赖方向固定为：`本附属 -> AOM / BetterMorph / Dark Doppelganger / Iron / GeckoLib`。AOM 不反向依赖本附属；卸载附属后 AOM 终焉和来源 Boss仍可运行，只失去中文覆盖与该 provider。

## 服务端与客户端

- 服务端：技能门禁、目标冻结、伤害、治疗、原生施法、召唤、60 tick 冷却和动作事实。
- S2C：玩家 UUID、稳定动作 ID、active、剩余 tick、cast UUID；只有开始、停止和追踪快照。
- 客户端：解析真实玩家的当前虚拟 identity，播放/停止来源 GeckoLib 动作；不决定任何业务结果。
- 客户端专用 Boss 条 Mixin 单列于 mixin 配置的 `client` 分区；common 源码不导入 `net.minecraft.client.*`。

## 兼容策略

直接引用 mandatory 依赖的公开 API/类型，不使用运行时反射。唯一私有访问是来源法术的 `hasLivingMinion`，通过范围明确的 Mixin invoker 暴露，并用精确版本哈希、方法名、描述符、private/static 标志测试锁定。

汉化 Mixin 只重定向精确来源方法里的 `Component.literal`，`require` 数与字节码合同一致；未知文本继续返回 literal。来源命名空间只打包 `lang/zh_cn.json` 和 `sounds.json`，不复制模型、纹理、动画、数据包或第三方类。

## 状态与清理

镜刃会话和视觉会话只保存在内存 Map，均有玩家 UUID、明确上限和清理入口，不写入 NBT。来源召唤法术生成的仆从仍使用来源持久数据，这是上游正式行为，不属于附属临时状态。

## 发布边界

发布产物必须是 reobf thin Jar。构建拒绝 `jarjar`、AOM、BetterMorph、Iron、GeckoLib、Dark Doppelganger和Architectury类；部署必须与同次验证的 AOM all Jar一起用安全模块同步到 PCL，并核对 SHA-256 与 mod id 唯一性。
